\subsection{Communication across moves}\label{sec:communication}

An \emph{endpoint} identifies a paglet independently of its network
address. It includes a hint about the current host. After a move, the
source keeps a forwarding record, called a \emph{tombstone}, for ten
minutes. If no usable local or forwarding record exists, a node looks
up the target in replicated location records. Consistent
hashing~\cite{karger1997consistent} chooses three hosts to hold these
records from the node's current view of live hosts. A higher move counter
replaces a lower one; a record naming the same host may refresh the
location. A majority must acknowledge a location update before transfer
commit. During a network partition, however, hosts may disagree on which
hosts are live, and a timed-out lookup may return an old location.
A location record helps routing; it does not reliably establish global
host failure.

Messages can be forwarded at most four times. Lookup caches expire after
ten seconds. Replies do not update old host hints held in endpoints, so
later messages may still need forwarding. An undeliverable request fails
or times out. A one-way send may receive an undelivered report, but such
reports are best effort. Neither entering a local queue nor crossing an
encrypted connection proves that the destination handler ran. After a
committed move, held messages are forwarded in mailbox order.

A \emph{pin} temporarily prevents a located paglet from moving while a
caller uses it. A host refuses new pins during an undecided move. Lookup
has separate limits on redirects and waits for a busy target; it cannot
treat a moving instance as permission to install a conflicting pin.
A pin is a lease: its promise expires after a limited time.
Its duration and grant policy limit the placement guarantee; a pin does not make a multi-host operation atomic.

Hosts exchange HTTPS frames over authenticated Noise
channels~\cite{perrin2018noise}. The handshake verifies the mesh identity
and enrolled host keys. A host without an inbound port can use relays,
but we did not test deployment behind real network address translation
(NAT). Preserving endpoints across moves still incurs message ordering,
queueing, expiry and changes to each host's view of the mesh.
