\paragraph{Mobile agents and mobility.}
Aglets represented a mobile agent as a Java object with callbacks for
creation, cloning, departure, arrival and
deactivation~\cite{lange1997aglets,lange1998aglets}. Java serialization
determined which connected objects could travel; communication used
proxies. \paglets{} retains these lifecycle operations but captures an
accepted instance's memory instead of requiring each object to support
serialization. In the terminology of code
mobility~\cite{fuggetta1998mobility}, this is weak mobility: execution
resumes at a handler boundary. Strong mobility instead resumes at an
arbitrary instruction, as in Agent Tcl~\cite{gray1996agentTcl}.
Making handler boundaries part of the programming model avoids the need
to reconstruct an active call stack.

\paragraph{Process migration and actors.}
Migrating an operating-system process requires preserving its external
resources and operating-system state as well as its
memory~\cite{milojicic2000migration,criu}. A paglet exposes less state,
but cannot transparently retain an open host file or socket. Actor
systems also process messages one at a time to control access to local
state~\cite{hewitt1973actor,armstrong2003thesis}. Orleans separates an
actor's identity (a \emph{grain}) from the instance currently running it
and the host chosen for that instance~\cite{bernstein2014orleans}.
In \paglets{}, the agent or its owner chooses placement, and a move
transfers the instance's current state. Messages and permissions must
remain valid across that transfer. This difference in placement does
not itself imply better throughput or availability.

\paragraph{WebAssembly snapshots.}
WebAssembly provides portable instructions, isolated program memory
(called \emph{linear memory}) and explicit declarations of functions or
state supplied by the host (\emph{imports})~\cite{haas2017wasm}.
Wizer saves initialized memory and globals so that a module can start
from a prepared state~\cite{wizer}. Initialization may use the
WebAssembly System Interface (WASI) or custom function imports, but
Wizer's documented restrictions exclude imported memories, tables and
globals. \paglets{} captures state repeatedly after handlers and also
transfers host records that WebAssembly itself does not describe.
Restoring active computations across CPU architectures needs additional
support: Tamura et al. use stack maps, which describe how to rebuild
the call stack at selected points in compiled
code~\cite{tamura2025crossisa}. \paglets{} avoids this requirement by
allowing migration only after a handler returns.

Faasm uses WebAssembly isolation and snapshots for efficient stateful
serverless execution~\cite{shillaker2020faasm}. \paglets{} instead manages
an agent that persists between calls, has a stable message endpoint and
carries permissions between hosts. We report no performance comparison
with Faasm. The WebAssembly Micro Runtime (WAMR) provides an interpreter
and optional ahead-of-time (AOT) compilation~\cite{wamr}. These support
the portable agent and CPU-specific compute-job paths in one runtime.

\paragraph{Earlier edition.}
The Python edition of \paglets{} transfers explicitly declared state
and requires application code to be installed on each
host~\cite{klukas2026pagletsNote}. The C++ edition captures instance state
and transfers modules identified by their hashes. Host-managed
permissions and the replicated-agent protocol are additional mechanisms.
The editions do not interoperate. We compare their state representation
and deployment requirements, but do not measure a speedup between them.
