\subsection{Image representation and page reuse}\label{sec:movement-image}

A memory image contains the module hash, mutable-global values, memory
page count and a \emph{manifest}, a list describing each 64\,KB page.
Pages containing only zeros need no payload; other pages are identified
by their SHA-256 hashes. Listing~\ref{lst:image-pages} shows the capture
loop. Guest pointers are offsets within linear memory, so restoring the
same bytes at those offsets preserves pointers without adjusting their
addresses or using custom object-serialization code. The saved format
uses a fixed byte order and checks page hashes before restoration.

% snippet: cpp/host/src/wasm_snapshot.cpp#paper_pages [caption={Capturing memory without interpreting application objects},label={lst:image-pages}]
\begin{lstlisting}[style=paglets-cpp,caption={Capturing memory without interpreting application objects \src{cpp/host/src/wasm\_snapshot.cpp}},label={lst:image-pages}]
const std::span<std::uint8_t> mem = instance.memory();
snap.page_count = static_cast<std::uint32_t>(mem.size() / page_size);
snap.pages.resize(snap.page_count);
for (std::uint32_t p = 0; p < snap.page_count; ++p) {
    const auto page = mem.subspan(std::size_t{p} * page_size, page_size);
    if (is_zero_page(page)) continue;
    snap.pages[p].zero = false;
    snap.pages[p].hash = sha256(page);
    snap.data.insert(snap.data.end(), page.begin(), page.end());
}
\end{lstlisting}
% /snippet

Capturing an image still requires scanning memory for zero pages and
hashing every nonzero page. Freeing a C++ object does not shrink Wasm
memory or necessarily clear its bytes. An instance can therefore retain
a large image after releasing a large buffer. Capturing all instance
state can cost more than saving only application-selected data.

The destination requests only missing pages. It compares the manifest
with a 256\,MB cache indexed by page hash. The cache evicts the least
recently used pages when full. Missing pages are transferred individually
using zstd compression; each must decompress to exactly 64\,KB and match
its declared hash. A return visit saves transfer only while the earlier
pages remain cached. Even an almost unchanged instance must send its
pages to an empty cache. Pages from other instances can also be reused
if their bytes match. The module is fetched separately by hash and must
pass the destination's module policy.

\subsection{Reconstructing host state}\label{sec:movement-record}

The memory image contains only guest state. A separate travelling record
carries the paglet's identity, owner, handle numbers, capabilities, timers,
pending-request identifiers and host-residency restrictions. The
destination preserves handle numbers but checks which permissions it can
reconstruct (Table~\ref{tab:movement-caps}). Handles that cannot be restored
are reported in the first \code{arrived} event; they are never silently
assigned to unrelated local resources.

Replies, timer notifications and host reports accepted before capture
travel with the image. They keep their message type and the identifiers
that match them to requests. For a pending request, the record stores its
remaining time allowance and when that allowance was measured. Arrival
subtracts the transit time, never less than zero, before setting a local
deadline. Repeated moves therefore cannot renew the original timeout.
Cross-host expiry assumes reasonably synchronized Unix clocks; local
deadlines use clocks that do not jump when the system time changes.
If a timer expires while the source is waiting for the move, its
notification survives arrival or rollback without being lost or delivered
by both paths.

\subsection{Preparation and ownership transfer}\label{sec:movement-protocol}

The source retains authority over the paglet until the transfer decision
is made. After capture, it stops running the instance and holds incoming
messages (Listing~\ref{lst:source-fence}). The scheduler releases the
record before passing the prepared departure to the mesh. Requesting a
move is therefore separate from permitting another host to run the agent.

% snippet: cpp/host/src/runtime.cpp#paper_departure_fence [caption={Stopping source execution before announcing departure},label={lst:source-fence}]
\begin{lstlisting}[style=paglets-cpp,caption={Stopping source execution before announcing departure \src{cpp/host/src/runtime.cpp}},label={lst:source-fence}]
rec.moving = true;
rec.image = std::move(*snap);
retire(rec);
rec.imports.reset();
departing.push_back(std::move(d));
\end{lstlisting}
% /snippet

The transfer has three stages (Figure~\ref{fig:movement-protocol}).
First, the source signs an offer identifying the mesh, both hosts, the
paglet, its signed identity record (\emph{passport}), module, page manifest
and travelling state. The destination checks the hosts' and owner's
enrollment, signatures, module restrictions and conflicting local
identities before requesting data. Second, it reconstructs the image
and host record but does not run the instance. It sends \code{move-ready}
only after this preparation. Third, the source updates the location
record on a majority of the hosts responsible for storing it, saves the
ownership decision durably, and sends \code{move-commit}. The destination
stores the arrival record before scheduling \code{arrived}. The source
then retires its record and forwards the held messages.

Silence does not authorize the destination to run the instance. After a
timeout it queries the source, which answers using its saved decisions.
Progress can therefore require the source to return. Rejection or failed
preparation permits rollback or a different destination. If ownership
has transferred but the destination cannot save required state, arrival
fails. Successfully sending bytes does not prove that the arrival hook
ran: the measured arrival acknowledgement is sent only after that hook
returns, or after an earlier failure.

These rules aim to prevent simultaneous execution during transfers
between cooperative, enrolled hosts. The distributed move protocol has
not been formally verified. Network partitions can block transfers, and
a host that lies about its state is outside the failure model. The rules
also depend on stable storage and retention of ownership decisions.
