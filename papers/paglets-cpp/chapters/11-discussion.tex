\paragraph{Benefits and costs of capturing instance state.}
Capturing one memory image removes custom state-export code and
preserves pointers and continuations without inspecting C++ object
layouts. The runtime must instead reject state it cannot capture, scan
all grown memory, restore only the matching module version, and define
how to reconnect host resources. It cannot automatically upgrade saved
state to a new module version. Interpreted agent code remains portable;
separate AOT jobs can improve compute speed while leaving their stacks
on the executing host. Suspending and moving an active handler would
require additional engine support and rules for its resources.

\paragraph{Different operations have different failure guarantees.}
Recovery from a checkpoint can repeat effects that occurred after it was
saved. An endpoint can remain valid across a move without guaranteeing
message delivery. Arrival can fail after ownership transfers. A job lost
with its host is not recovered like a replicated agent. The zombie
service selects one ranked chain of work and merges observations, but
does not impose one global order on external actions during partitions.
The number of accepted results also depends on sink redirects.
These distinctions matter: a successful local call does not imply that
an operation took effect exactly once across the whole system.

\paragraph{Trust and isolation.}\label{sec:discussion-trust}
Module checks, capabilities and worker sandboxes restrict what untrusted
guest code can do to a host. They do not protect an agent from the host
that holds its unencrypted image. An enrolled malicious host can read or
alter that image and act in the agent's name. Revocation, module policy
and residency restrictions therefore assume an organization that trusts
its hosts. They do not provide Byzantine fault tolerance, which includes
arbitrary dishonest behavior, or confidential computing, which protects
state from the executing host. Windows workers use Less Privileged
AppContainers without network capabilities, plus restricted security
tokens and job objects to limit processes. Isolation differs by platform
and has not received an independent security review.

\paragraph{What stronger verification would require.}
Using the implementation in the checker avoids a separate protocol
model, but the surrounding environment and search simplifications still
need justification. Future work includes comparing full states instead
of hashes, proving counter renaming correct, deliberately inserting bugs
to assess the tests, and completing three-replica exploration or proving
that a smaller search suffices.

A further goal is eventual recovery on every weakly fair execution:
actions that remain continuously possible must eventually run, and recovery must
then complete. This corresponds to checking AG AF with a search for
nonterminating fair cycles. The current AG EF check only shows that a
path to recovery exists from each reachable state. A cycle with an exit
can pass that check even if execution keeps taking the cycle.
Larger meshes, real NAT paths and comparisons using equivalent
applications are also needed before making broader performance or
availability claims.
