Moving computation to data can reduce repeated remote interaction and
allow work to continue after the initiating client disconnects. A mobile
agent makes this idea explicit: it is a program with an identity, local
state and message handlers, and it can move between
hosts~\cite{lange1997aglets,karnik1998design}. Moving the program file is
only part of the problem. The system must also decide which execution
state to transfer, which resource references remain valid, and which
host may run the agent if a transfer fails.

\paglets{}/cpp addresses this problem by restricting when state can move.
An agent, called a \emph{paglet}, consists of one WebAssembly module and
one running instance of it. The host calls one handler at a time and
allows migration only between calls. It rejects modules whose state
cannot be captured. For accepted modules, the instance's memory and
mutable global variables are sufficient to resume execution. C++ objects,
heap pointers and registered callbacks for pending operations therefore
survive a move without custom code to save and restore those objects.
The host transfers permissions, timers and pending requests separately.
This is \emph{weak mobility}: it does not capture an active WebAssembly
call stack.

This restriction also separates coordination from long computations.
An agent can remain interpreted and able to move, while a separate
compute job runs code compiled for its current CPU. Replicated agents
can reuse the same state-capture mechanism to save checkpoints for
recovery, provided that they save state before sending messages that
depend on it. The paper presents three contributions:

\begin{enumerate}[leftmargin=2em]
\item An execution model that captures WebAssembly state between handler
  calls, keeps permissions under host control, and defines the order of
  lifecycle events, request replies and recovery notifications
  (Section~\ref{sec:model}).
\Needspace{5\baselineskip}
\item A migration protocol that separates page transfer, destination
  preparation and the ownership decision. Message endpoints remain
  usable across moves; compute jobs have a separate execution path
  (Sections~\ref{sec:movement} and~\ref{sec:mesh}).
\item A replicated-agent protocol whose transition function runs both in
  the library and in tests using bounded fault models, simulated time
  and physical hosts (Sections~\ref{sec:zombies}
  and~\ref{sec:evaluation}).
\end{enumerate}

The contribution is the integration of these mechanisms and the evidence
from their implementation. We do not propose a new WebAssembly snapshot
format or consensus algorithm. The paper distinguishes measured behavior,
properties checked in finite models and claims that remain untested.
In particular, it does not show that mobility outperforms remote calls,
or that checking small fault models proves eventual recovery under
arbitrary timing.
