\begin{abstract}
Mobile agents need a way to carry their execution state between hosts
while keeping access to host resources under host control. We present
\paglets{}/cpp, a runtime in which each agent runs as one WebAssembly
instance. It captures the instance's memory and mutable global variables
between handler calls. Host-managed permissions travel in a separate
record. The destination prepares the instance but starts it only after
the source commits the transfer of ownership. Message endpoints remain
usable after a move. Long computations run as separate, cancellable jobs,
optionally compiled for the executing host's CPU. A replication protocol
orders saved execution states, merges recorded observations and detects
duplicate results. The same protocol code runs in the software library
and a model checker that explores possible execution states. In tests on
three machines on one local network, 480 moves exercised four image sizes
and page-cache reuse; a 16\,MB return move sent two pages instead of 258.
Ten two-replica model configurations were explored completely; two
three-replica configurations were checked only to a search depth of
11 steps. These results
demonstrate feasibility and identify costs and failure limits. They do
not establish an advantage over remote calls, native execution or other
fault-tolerant systems.
\end{abstract}
