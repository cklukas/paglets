## What was built

- **`cpp/host`**: host library.
  - `wasm/engine`: WAMR runtime, modules (import validation before loading),
    instances with memory and stack limits, calls, termination from another
    thread, guest log import, paglet ABI v0 message calls.
  - `wasm/binary`: runtime-independent reader for imports, globals, exports
    and memory limits; import allowlist per trust class; check that every
    mutable global is exported.
  - `wasm/snapshot`: memory images (64 KB pages with SHA-256 per page, zero
    pages elided, mutable globals, bound to the module hash), serialization
    format `PGIMG001` with integrity check.
  - `wire/reflect` + `wire/json`: MessagePack and JSON codecs generated by C++26
    reflection (structs as maps, enums by name, vectors, optionals, bytes), and
    canonical schema type names.
  - `paglets-host` (M0: build information) and `paglets-spike` (inspection,
    image save/resume, measurements).
- **`cpp/tools/schema_gen`**: compiled with GCC 16 per guest; reflects over the
  guest's message namespace and emits plain C++ encoders/decoders plus a JSON
  schema descriptor for clang/wasm.
- **`cpp/sdk`**: guest side of ABI v0 (`paglets_alloc`, `paglets_handle`,
  `paglets_free`, `paglets_abi_version`, import `paglets.log`).
- **`cpp/examples/counter`**: example paglet whose state is ordinary C++
  objects (vectors, strings) moved by memory images.
- **Tests**: 34 unit tests plus a two-process image test in CTest; clean under
  AddressSanitizer and UndefinedBehaviorSanitizer.

## Cross-architecture memory images

Same `counter.wasm` (SHA-256 `0fc8e7bc…c04af`) on all hosts:

| From | To | Image | Result |
|---|---|---|---|
| macOS arm64 (GCC 16) | Linux arm64, Raspberry Pi 4 (GCC 14) | 640 KB, value 210 | resumed 210, continued to 216 |
| Linux arm64 | macOS arm64 | 128 KB, value 28 | resumed 28, continued to 29 |
| Linux arm64 | macOS x86-64 (Apple clang, Rosetta 2) | 128 KB, value 28 | resumed 28, continued to 31 |
| macOS x86-64 | Linux arm64 | 384 KB, value 45 | resumed 45, continued to 46 |

Memory images are independent of CPU architecture, operating system, host
compiler and standard library, as expected from the Wasm memory model.

implementation); a faster hash is an easy later improvement.

## Findings

1. **WAMR runs `_initialize` itself** for modules that import WASI; calling it
   again traps inside wasi-libc. The host calls it only for modules without
   WASI imports.
2. **Hardware bound checks reserve 8 GB of virtual memory per instance.** On
   kernels with a 39-bit address space (Raspberry Pi OS, `CONFIG_ARM64_VA_BITS=39`)
   a process can hold only about 60 instances. Software bound checks remove the
   limit; they make instantiation and host calls faster but message handling
   about 2.5 times slower on macOS. New build option
   `PAGLETS_WAMR_HW_BOUND_CHECK`; the right default per platform (and the
   number of instances per worker process, WP5) should follow from this.
3. **Termination works** with WAMR's thread manager enabled: an endless loop is
   stopped from another thread within milliseconds in every configuration.
4. **C/C++ guests have exactly one mutable global** (`__stack_pointer`). Linking
   with `-Wl,--export=__stack_pointer` makes it capturable; the host refuses
   images for modules with unexported mutable globals.
5. **Fast interpreter is about 10 times faster** than the classic interpreter
   for message handling; it stays the default. AOT and JIT modes were not
   measured (they need the LLVM-based `wamrc`/JIT build); follow-up for WP5.
6. **Reflection confinement works**: the host builds and passes all
   non-reflection tests with GCC 14 and Apple clang. Only the wire codecs and
   the schema generator need GCC 16.
7. **GCC 16 reflection details**: `std::int64_t` and friends are
   using-declarations in libstdc++ and cannot be reflected (use `::int64_t`);
   variables of consteval-only type (`std::span<const std::meta::info>`) are
   not allowed in runtime functions, so `template for` iterates over the
   expression directly.
8. **GCC does not preprocess WAMR's `.s` files** (clang does); they are built
   with `-x assembler-with-cpp`.
9. **UBSan reports misaligned accesses in WAMR's fast interpreter**, which reads
   its compiled bytecode unaligned on purpose; the alignment check is disabled
   for WAMR only.
10. **Host → guest call overhead (~0.4 µs)** is mostly WAMR's call setup;
    export lookups are cached. Batching several messages per call is an
    option for WP5 if needed.
